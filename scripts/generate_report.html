2. Remediated Bugs & Architectural Hardening

1. Systemic Timezone / UTC Date Shift Critical

Root Cause: Systemic calls to .toISOString().split('T')[0] converted local device dates to UTC dates. In timezones east of UTC (e.g. IST UTC+5:30), tasks scheduled for today disappeared between 00:00 and 05:30, and the calendar month view suffered off-by-one day grid displacements.

Solution: Created src/utils/date.ts offering deterministic local date calculations (getLocalDateString, addDaysToLocalDate, isOverdue). Updated calendar.tsx, tasks.tsx, index.tsx, hub.tsx, TaskCard.tsx, taskRanking.ts, and repository.ts.

2. SQLite Cold-Start Database Initialization Race Condition High Risk

Root Cause: getDb() returned the SQLite database handle before executing schema DDL migrations, causing potential no such table fatal crashes on cold launch.

Solution: Refactored getDb() in src/database/db.ts to execute initDatabaseSync() synchronously on first handle resolution. Resolved circular module imports between db.ts and repository.ts.

3. Notification Interaction & Deep Linking Integration Core Feature

Root Cause: Notification tap events lacked an event listener, leaving the app on the current screen without navigating to the task triggering the alarm.

Solution: Attached getLastNotificationResponseAsync and addNotificationResponseReceivedListener in root src/app/_layout.tsx, automatically routing user taps to /task/[id].

4. Task Duplication, Snooze, & Subtask Context Desynchronization Moderate

Root Cause: Task duplication in src/app/task/[id].tsx omitted subtasks/reminders and mutated database state directly without calling AppContext methods, leaving UI stale until app restart.

Solution: Re-routed duplication through createTask() with full subtask/reminder replication, connected snooze to local date math, and added refreshAllData() on subtask addition.

5. Form Usability & Native Date/Time Selection Usability

Root Cause: Task deadline entry relied entirely on manual string typing. On smaller Android screens, the soft keyboard concealed submission buttons.

Solution: Integrated @react-native-community/datetimepicker with visual calendar and clock dialogs in create.tsx. Wrapped form screens in KeyboardAvoidingView with keyboardShouldPersistTaps="handled".

6. Flutter Android Notification Resource Mismatch High Risk

Root Cause: The Flutter companion service referenced @mipmap/ic_launcher, which did not exist on disk, causing fatal runtime crashes during notification initialization on Android.

Solution: Aligned initialization to point to @drawable/ic_launcher in flutter_app/lib/services/notification_service.dart.
